FOUND / FIXED DURING v163
1) Multi-replica without shared ownership could permit split-brain room writes.
   Fix: Redis room-owner lease + monotonic fencing token. Stale owner persistence is rejected.
2) Non-owner HTTP routing had no client recovery path.
   Fix: ROOM_OWNER_MISMATCH includes ownerUrl/ownerInstanceId; SDK retries once and persists moved endpoint.
3) Redis durability needed to precede local SSE mutation broadcast.
   Fix: Redis mutations suppress room broadcast until fenced persistence succeeds, then flush.
4) Redis failover-restored rooms needed the same reconnect grace / bot takeover boundary as process restart.
   Fix: recovery grace armed on lazy room restore.
5) SSE-close disconnect/bot mutations also need Redis durability.
   Fix: disconnect and tournament expiry paths persist through the fenced store.
6) Generic IP-only rate limiting could throttle four valid players behind the same NAT during snapshot-heavy play.
   Fix: authenticated buckets use IP + seat bearer; unauthenticated create/join remains IP scoped.
7) v163 session migration initially left the v162 reconnect key behind on explicit leave.
   Fix: clearSession removes v163 and legacy v162 entries.
8) Production misconfiguration needed fail-closed readiness.
   Fix: wildcard production CORS, multi-replica file mode, missing owner URL, and missing Redis URL fail readiness.
9) Redis-mode rejected action IDs also need durable fingerprint memory.
   Fix: Redis action route persists the room even for canonical 4xx action results, so rejected clientActionId reuse remains protected after failover.
