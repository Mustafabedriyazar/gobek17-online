============================================================
1. USER-LOCKED RULE CHANGES
============================================================

A) SAHTE OKEY — SINGLE STANDARD OKEY AUTHORITY
- NORMAL and BIG hands now both use a numbered indicator.
- Real Okey = same-color next number of indicator (13->1 only for Okey identity).
- Sahte Okey (★) is NEVER wildcard/joker.
- Sahte Okey represents the real Okey's color+number as a natural tile in meld/score/pair logic.
- Visual face stays ★.
- Example: black 4 indicator => real Okey black 5 => Sahte Okey behaves as natural black 5; black 4-★-6 is legal.
- Old BIG_FAKE and FAKE_INDICATOR_BIG runtime paths are removed.
- If a fake tile is encountered while choosing the indicator, it is skipped and the first numbered tile is chosen as indicator; fake stays in deck.

B) OPENED MELDS ARE IMMUTABLE
- Once opened, existing meld tiles cannot be removed, reordered, repartitioned, moved into another meld, or split.
- SERIES process is endpoint-only (far left / far right).
- A SERIES meld can receive at most TWO processed tiles total after opening (processAdds <= 2).
- Example: blue 4-5-6-7-8 + blue 9 remains one meld 4-5-6-7-8-9; no 3+3 split. Blue 10 may be added as the second process; a third addition is RED.
- Existing RENKSIZ SERI PER max-4 rule remains.
- PAIR processing remains a separate 2-tile path creating a new PAIR meld; it does not append a single third tile to an existing pair.
- Long-press meld reposition/zoom authority removed; canonical layoutMelds() remains the single geometry authority.
- Illegal middle/third endpoint process intent does not fall through to FREE board; source tile is restored.

C) SIDE-DISCARD TAKE / RETURN
- Side-taken tile is a pending tile.
- If used legally in OPEN / new PER / PROCESS, taker pays represented tile value x10 to SELF.
- If it cannot be used, is cancelled, or player attempts another discard:
  * taker pays represented tile value x10 to SELF,
  * exact physical pending tile returns to source player's discard area,
  * taker's normal rack tile is not discarded,
  * turn advances atomically.
- TAKE_CANCEL cannot bypass penalty.

============================================================
2. ROOT CAUSE / CONFLICT FINDINGS
============================================================

1) Special fake-Okey authority was fragmented across runtime modes.
   The browser/server engine still had BIG_FAKE and FAKE_INDICATOR_BIG branches in addition to normal INDICATOR behavior. These were removed so one numbered-indicator authority governs both NORMAL and BIG hands.

2) Opened meld mutation had multiple legacy behaviors.
   The old 5+1 female-run path could split a six-tile meld into 3+3, contradicting the locked 'opened meld never moves/splits' rule. That split path was removed. Existing meld order is now preserved after the initial canonical open normalization, and SERIES processing is endpoint-only with a cumulative two-add limit.

3) Presentation had a separate long-press reposition authority.
   activateMeldHold could visually reposition/zoom opened meld content independently of canonical engine layout. It was removed. Existing v149 transform hardening and computed-transform audit remain active.

4) Side-take behavior had an old retention/penalty model.
   Pending side tile could be retained/handled in a way incompatible with the new 'use it or return it' rule. TAKE_PENALTY/TAKE_CANCEL/discard-with-pending now converge on one atomic return+penalty transaction.

5) Trial/error caught a strict-mode browser defect before packaging.
   Initial v152 browser patch used:
       var pd=st.pending;st.pending=null,amount=tv(pd.tile)*10;
   where amount was undeclared under strict mode, producing ReferenceError: amount is not defined.
   Corrected in browser and server engine to declare amount before clearing pending:
       var pd=st.pending,amount=tv(pd.tile)*10;st.pending=null;
   Browser parity was rerun after the fix and passed.
